# ADR-0005: 队列式增量主题聚合

## 日期

2026-08-08

## 状态

已采纳

## 背景

原主题聚合每次取「最新 50 条未读」全量重建主题组，存在三个问题：

1. 窗口截断：未读积累 >50 条时，更早的未读永远不会被聚合（数据静默丢失）
2. 无历史上下文：AI 不知道已有哪些主题 → 同类内容每次聚成不同主题名（主题漂移）
3. 全删重建：每轮 DELETE 全部旧主题组再重建，组 ID 漂移、历史丢失

若改为全量输入（2000+ 条）会超出单次 AI 上下文限制。

## 决策

采用「队列式增量聚合」：

- raw_items 新增 aggregated_at 字段（NULL = 未聚合，作为聚合队列标记）
- 每轮消费一批（默认 100 条）= 新数据优先（保证最新热点立即可见）+ 最旧未聚合补足（消化积压）
- 聚合前把「该 source 已有主题列表」注入 AI prompt 作为历史上下文，要求优先归并到已有主题
- 存储改为增量 upsert：同名主题复用（不重建），只有确实无法归入的新方向才新建主题
- 聚合后删除该 source 下已无任何 items 的空主题，并标记本批已聚合（队列轮转）

## 影响

- 正面：所有数据最终都会被聚合（无窗口截断）
- 正面：主题名稳定不漂移（AI 有历史上下文，同名复用）
- 正面：每轮成本固定（100 条/批），不随数据量增长
- 正面：新数据立即可见（批次内新数据优先）
- 代价：增量 upsert 早期归并错误会留存，需后续人工/定期校正

## 备选方案

- 全量分批 + 批间合并：每轮取全部未读分批聚类再合并。成本随数据量线性增长，批间合并复杂度高，未采用
- 全删重建 + 历史上下文：仍无法解决窗口截断，且重建后主题组只反映本批数据，未采用
