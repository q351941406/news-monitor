# ADR-0010: 移动端优先的交互与布局策略

## 日期

2026-09-25

## 状态

已采纳

## 背景

站点的主要读者是**在手机上碎片化浏览**的开发者，但 UI 是按桌面优先写的，
移动端只能靠把桌面版塞进窄屏来应付。窄屏（375px）上实测暴露的问题：

1. **功能在小屏上直接丢失**：Header 的「设置」入口只存在于桌面操作区
   （`hidden md:flex`），汉堡菜单里漏了 —— 小屏用户**无法到达设置页**。
2. **触控目标过小**：主题条目上的「已读 / 未读」胶囊只有约 22px 高，
   低于移动端触控下限，密集列表里极易误触相邻条目。
3. **横向滚动条白占空间**：来源标签栏写了 `scrollbar-hide` 类，但该类从未
   定义过 —— iOS/Android 上留下一条 6px 灰条。
4. **选中项可能滚出视野**：标签条横向滚动，点中右侧标签后该标签常被顶到
   屏幕外，页面看似"没反应"。
5. **抽屉关不掉**：移动菜单只能靠再点一次汉堡或点菜单项关闭；Esc 无效、
   打开时背景仍可滚动。
6. **桌面专属布局在小屏不可用**：仪表盘的 7 列运行日志靠 `overflow-x-auto`
   横向滚动，表头上下文丢失、错误信息被 `truncate` 掉看不见。
7. **触屏没有 hover**：柱状图的数值只在 `group-hover` 时出现，触屏上**永远看不到**。
8. **嵌套滚动手势冲突**：展开详情里的原文区 `overflow-y-auto`，在手机上会和
   页面竖向滑动抢手势，出现"想滑页面却把正文框滚走了"。
9. **安全区缺失**：未声明 `viewportFit: 'cover'`，刘海/灵动岛与底部
   home indicator 机型上，sticky 顶栏会压状态栏、页脚会藏进指示条。
10. **iOS 输入框自动缩放**：移动端 input 字号 <16px 时 Safari 会自动放大
    整页，导致布局被撑破。

## 决策

**移动端不是桌面版的缩放，而是一套有自己布局与交互契约的形态。**

### 1. 布局：断点两侧各自成立

每个页面都必须给出窄屏形态，而不是靠 `flex-wrap` 侥幸不溢出：

- 仪表盘运行日志：窄屏用**卡片列表**（`md:hidden`），桌面保留表格（`hidden md:block`）。
  表格横向滚动在窄屏等于信息不可达。
- 归档页筛选栏：窄屏纵向堆叠，各组按钮组**自身横向滚动**；桌面恢复同行排列。
- 卡片内边距、标题字号按 `sm:` 断点收放，窄屏优先保证一屏能看到更多条目。

### 2. 触控：44px 是下限

- 菜单项、按钮、分页等直接给 `min-h-11`（44px）。
- 紧凑排版里的小胶囊（已读 / 未读 / 展开箭头）**视觉尺寸不变**，
  用透明伪元素 `before:-inset-2` 把可点区域外扩 —— 保住排版密度，
  同时让手指有足够落点。
- 输入框移动端字号 ≥16px，避免 iOS 自动缩放。

### 3. 交互：抽屉按原生手势契约实现

移动菜单改为「全屏遮罩 + 固定抽屉」：打开锁 `body` 滚动、点遮罩关闭、
Esc 关闭并把焦点还给触发按钮、`aria-expanded` / `aria-controls` 播报状态。
桌面与移动两套 DOM 并存是刻意的（各有独立布局），用 CSS 断点互斥显示。

### 4. 滚动：一律用滚动容器，不用嵌套滚动

窄屏**不建**内部滚动区（详情原文、图表等），内容自然展开；
`sm:` 以上才加 `max-h + overflow-y-auto` 约束高度。横向滚动容器统一
`scrollbar-hide` + `overscroll-x-contain`，避免滚动链把整页带偏。

### 5. 悬停专属信息必须有非悬停出口

任何只在 `:hover` 呈现的数据（图表数值），窄屏都要补一份可读的文字清单，
否则等于不存在。

### 6. 平台能力：viewport / 安全区 / manifest

- `viewportFit: 'cover'` + `themeColor`，`env(safe-area-inset-*)` 工具类
  （`.pt-safe` / `.pb-safe`）供顶栏与页脚避让。
- `min-h-dvh` 而非 `100vh`，规避移动浏览器地址栏导致的高度跳动。
- `manifest.ts` + standalone 图标，支持"添加到主屏幕"。
- 去掉 iOS 默认的灰色点按高亮，长串文本 `overflow-wrap: break-word`。

## 结果

- 首页 / 归档 / 设置 / 仪表盘在 375px 与 390px 下横向溢出均为 0。
- 小屏功能与桌面端对齐（设置页可达）。
- 键盘与读屏用户可完整操作展开/收起（`role` + `tabIndex` + Enter/Space）。

## 验证方式

jsdom 不做布局，测不了窄屏，所以分两层：

- **单测**（`src/app/components/__tests__/mobile-adaptation.test.tsx`）：
  锁结构与类名 —— 设置入口存在、抽屉 Esc/锁滚动、热区类、滚动容器配置。
  注意桌面区与抽屉同时存在于 DOM，查询须用 `within('#mobile-menu')` 限定。
- **e2e**（`e2e/mobile.spec.ts`）：真实 Chromium + 375px 触屏视口，
  测 jsdom 测不了的部分 —— 实际横向溢出量、触控区域尺寸、抽屉点击行为、
  表格与卡片的断点切换。

用独立 spec + `test.use` 而非新增 Playwright project，避免整个 e2e 套件
在两个视口下跑两遍、CI 时间翻倍。

## 代价

- Header 桌面区与抽屉两套 DOM 并存，维护时需同步两份。
- 仪表盘运行日志一屏信息密度下降（换来的可读性）。
- 部分样式判断（44px 触控、横向溢出）只能在真实浏览器里断言，单测覆盖不到。
